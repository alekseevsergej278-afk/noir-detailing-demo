# NOIR — кинематографичная Desktop-сцена

Развитие существующего статического сайта для GitHub Pages. Одна BMW M5 F90 проходит восемь этапов при обычной прокрутке. Прежние блоки студии, услуги, цены, процесс, портфолио разных марок, контакты, демонстрационная форма и футер сохранены.

## Запуск

Запустите HTTP-сервер из этой папки: `python -m http.server 8000`. Откройте http://localhost:8000. Через file:// модель не загрузится. Готовый JS включён в репозиторий; установка пакетов для просмотра и GitHub Pages не требуется.

Исходник сцены: assets/js/cinematic-source.js. Стили: assets/css/cinematic.css. После изменения JS: `npm install`, затем `npm run build:3d`. Используется Three.js 0.181.2 с GLTFLoader, MeshoptDecoder и Reflector. Дополнительная библиотека анимации не нужна.

## Защищённая модель

assets/models/bmw-m5-f90-source.glb — 17 537 644 байта, 259 930 треугольников, 361 mesh, 96 материалов и 55 изображений текстур.

SHA-256: 8d064b8dc6412bc324041d3f964c305994e683b6d427381958ce2807388cb776.

Файл скопирован побайтно из ранее скачанного источника. Геометрия, топология, UV, нормали, материалы и текстуры не пересохранялись и не изменялись. Для отображения используются обратимые runtime-копии материалов кузова и чёрной тонировки: исходные объекты материалов и GLB остаются нетронутыми. Остальные материалы используются напрямую.

Стёкла прозрачные с лёгким холодным оттенком: видны сиденья и панель приборов. Цвет кузова зафиксирован в графите; переключателя цветов нет. Старый сохранённый выбор браузера не используется. Слои полировки используют тот же графитовый оттенок.

`npm run verify:source` проверяет хеш, данные GLB, восемь глав и сохранение семи существующих содержательных блоков относительно резервной ветки. Прежний инструмент оптимизации запрещает обработку файла с этим хешем. Дополнительная оптимизация модели не нужна.

## Сценарий

1. Hero: графитовый металлик, прозрачные окна, ракурс 3/4, проявление студийного света и небольшое движение камеры.
2. Осмотр: приближение к капоту, отдельный матирующий слой с мелкими процедурными микрорисками.
3. Полировка: проход восстановления снимает слой дефектов и добавляет независимый слой блеска.
4. Керамика: световая волна, прозрачный слой и инстансированные капли, расположенные raycast по исходному капоту.
5. PPF: прозрачный слой на геометрии оригинального капота, прижатие по нормалям и отдельная маска переднего бампера.
6. Интерьер: камера проходит внутрь исходной модели. Используются существующие сиденья, консоль, приборы, кожа и текстуры.
7. Результат: выход наружу и полный оборот на 360° по прокрутке.
8. Финал: возвращение к 3/4 и ссылка на существующую форму #contact.

Визуализация покрытий иллюстративная. Эффекты — обратимые дополнительные поверхности со своими материалами. Они используют ссылки на исходную геометрию и не заменяют её. PPF повторяет поверхность исходных деталей.

## Рендеринг

Один canvas, renderer и одна загрузка GLB. Пассивный scroll только запрашивает кадр; камера, FOV, поворот, свет и эффекты интерполируются по общей шкале. Камера, автомобиль и закреплённый текст используют одно сглаженное положение прокрутки. Монотонная кубическая интерполяция сохраняет непрерывную скорость без выхода за ключевые координаты. Позиции секций измеряются после загрузки шрифтов, при resize и изменении высоты main. Нет перехвата wheel, дополнительной прокрутки или блокировки страницы.

Студия использует PMREM-окружение из софтбоксов, мягкий фон, ограниченное размытое отражение пола 1024×512 и контактную тень. Каскады теней и тяжёлый постпроцессинг не применяются. Pixel ratio ограничен 1.5; при длительных медленных кадрах снижается до 1. Отражение обновляется с текущей камерой на каждом отрисованном кадре и плавно затухает перед крупными планами. Геометрия остаётся прежней. Частота рендера ограничена примерно 60 FPS.

Дополнительные шейдеры прогреваются перед показом модели. Невидимые эффекты отключены. За непрозрачными прежними блоками и в скрытой вкладке рендер приостанавливается. Ресурсы освобождаются при уходе со страницы. Панель управления сценой и полоса повторяющихся услуг удалены. Начальное появление запускается автоматически и завершается; дальнейшим движением управляет обычная прокрутка. Системный prefers-reduced-motion отключает декоративное появление, параллакс фотографий и реакции движения интерфейса. Основная демонстрация автомобиля по скроллу работает автоматически. Отдельный спокойный сценарий с устойчивой камерой доступен по явному параметру ?motion=reduced. При ошибке WebGL есть повторная попытка, услуги и форма остаются доступны.

## Границы демо

Целевые размеры: 1920×1080, 1600×900, 1440×900, 1366×768. Новая мобильная или планшетная версия не разрабатывалась. Форма сохранила прежний демонстрационный режим: обязательные поля, сообщение и очистка; заявки никуда не отправляются. Рабочие контакты студии в исходном демо ещё не заданы.

Плавность зависит от GPU и браузера. Снимки и результаты локальной проверки находятся в verification/. Измерения встроенного браузера не гарантируют 60 FPS на любом оборудовании.

## Проверка новой анимации

`npm run verify:motion` проверяет точное попадание в ключевые состояния, отсутствие выбросов, непрерывность скорости и детерминированное движение назад. `npm run verify:source` защищает исходный GLB и прежний контент.

Для диагностики доступен `?perf=1`: скрытый DOM-output scene-diagnostics содержит число загрузок модели, показатели рендера и проверки исходных материалов. Обычный адрес включает движение камеры по прокрутке. `?motion=reduced` явно включает устойчивый внешний ракурс; системное уменьшение движения само по себе не блокирует демонстрацию услуг.
